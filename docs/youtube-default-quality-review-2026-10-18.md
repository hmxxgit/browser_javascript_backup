# YouTube 默认画质 2.2.0 审查与验证

日期：2026-10-18（Asia/Shanghai）。审查基线：`ef39e243d3572a28175090001faf9591d3ba7433`，通过 SSH fetch 确认为当时远程 `main` 最新提交。本地工作区开始时干净。

## 审查发现与处理顺序

“模拟复现”表示在真实 Chromium 中运行离线播放器样例，不能解释为已在真实 YouTube 账号上发生。以下前六项新增测试在未修改的 2.1.1 上全部失败。

| 优先级 | 问题及证据 | 影响与修复 |
| --- | --- | --- |
| P0 | 模拟复现：API 尚未附着时，原生 480P 选择未被 `yieldToUser()` 锁定 | API 附着后可能覆盖手动选择；按事件所属播放器识别操作，独立 `manualOverride` 同步锁定。无 URL ID 的初始手动锁也随同一播放器首次身份发现保留 |
| P0 | 模拟复现：URL 已是 B、播放器仍是 A 时，`findPlayer()` 回退绑定 A | 旧版已有写入身份检查，未据此证明会错写 A；但错误绑定影响事件归属。现在明确 URL ID 无匹配时返回空，等待目标播放器 |
| P1 | 模拟复现：可用原生选项仍被全局 Range API 存在性检查拦截 | 原生路径不再依赖 Range；仅在确实使用回退路径时检查 Range 函数，显式不可播放 / 付费档位不能绕过原生限制 |
| P1 | 模拟复现：菜单初始化第一次抛错后，布尔 `menuPrepared` 永久阻止恢复 | 改用 `preparing/pending/ready/failed`，每次访问至多两次准备，异步等待窗口 1.5 秒，失败后可有限恢复 |
| P1 | 模拟复现：画质数据数组夹杂 null 时，合法选项也无法匹配 | 严格验证条目类型、`isPlayable === true`、非付费标签和菜单所属播放器；无合法选项不盲目写入 |
| P2 | 模拟复现：`pagehide` 解绑后，后续文档事件又绑定播放器 | 独立挂起标志拦截排队刷新和计时器；清理临时菜单，直到 `pageshow` 才恢复 |
| P0/P1 | 防御增强及新回归：菜单初始化回调期间视频、广告状态或可用列表可能改变 | 所有画质写入前重新校验当前会话、手动锁、身份、实际档位和选项归属；没有将这种构造的竞态声称为真实网站已发生 |
| P1 | 风险修复及新回归：立即关闭异步菜单可能销毁尚未生成的选项；恢复焦点可能干扰用户 | 有限保留准备面板；可信输入立即解除脚本对临时 UI 的占用，只有实际激活画质才设置手动锁；不强行关闭用户已有面板或抢焦点 |
| P2 | 优化及新回归：通知突发重复查找播放器，预加载媒体可能重置活动稳定窗口 | 合并同一任务内通知；只有活动播放器的媒体事件重置稳定证据。300 次通知的测试测得 1 次播放器扫描 |

## 保留的行为与状态转换

- 默认 1080P；配置值与 `youtube-default-quality.preferred-height` 存储 Key 不变。只从实际列表选择不高于首选的最高档位。
- `waiting` 可读取和有限准备；写入过程中临时切为 `attempted` 防止同步重入。确认首选为目标后进入 `applied`；结果不明或异常停在 `attempted`；额度耗尽进入 `expired`。
- 原生选择读回明确 Auto 时先等待确认，再按原有上限尝试，画质动作最多 3 次。Range 和抛异常的写入不重复。成功确认后不会因 ABR、播放事件或打开菜单重新设置。
- 实际可信画质激活（包括 Auto）设置独立手动锁并进入 `manual`；终止挂起确认、计时器及临时菜单，即使此前还没有完成自动设置。脚本自己的合成点击不触发手动锁。
- A → B → A 每次建立新访问；参数、暂停、seek、全屏、同 ID 的播放器替换不解锁终态。整页刷新仍创建新访问。
- 临时菜单结束时清理样式与引用；恢复操作抛错也不能跳过清理。对新身份、用户介入或页面挂起不抢焦点。

没有改动 GM 配置界面、Shadow DOM、Trusted Types 构建方式，没有新增依赖、追踪或外部请求。菜单内部标识、API、DOM 结构沿用已验证接口，不使用失效的 `setPlaybackQuality()`。

## 时机、次数与性能

保留媒体已有可播放数据、播放器播放 / 暂停状态及同一媒体源稳定至少 2 秒的保护，没有充分证据支持缩短。它是就绪检查后的稳定窗口，并非页面加载后固定延时即认定播放器可用。

45 秒 / 30 次就绪额度、首次主内容播放的一次补充额度，以及三次原生画质尝试上限保持不变。菜单准备单独限制为每次访问两次，每次异步窗口 1.5 秒。用户已打开设置但选项未生成时等待其查看或关闭，可能推迟默认设置，优先避免操作冲突。

始终至多一个自动化计时器，另有一个合并通知的微任务；没有常驻高频轮询或 MutationObserver。媒体事件不再逐个全页扫描，终态释放媒体和菜单临时引用。

## 已执行测试

命令：

```sh
node --check youtube-default-quality.user.js
npm test
X_UI_BROWSER=chrome node --test tests/youtube-default-quality.test.cjs
node tests/youtube-default-quality.live.cjs
node tests/youtube-default-quality-auto.live.cjs
git diff --check
```

离线完整回归：Edge **127/127**；YouTube 回归：Chrome **114/114**。原有配置、降级、A → B → A、列表 / 自动连播事件、慢初始化、广告、API 异常、重复注入和手动保护等测试继续通过。新增 18 项覆盖上表修复和保护边界；它们不等于真实播放列表自然播完、真实 Shorts 连续滑动的端到端验证。

真实网站基础检查：Edge 155.0.4283.60 独立临时环境，8 个检查点通过：

1. 同时存在 4K / 1440P / 1080P 时选择 1080P。
2. 实际解码帧达到 1080P。
3. 原生手动 4K 保持。
4. 原生手动 480P 经暂停 / 继续、seek、全屏后保持。
5. 点击真实推荐视频，经 SPA 切换应用默认策略。
6. 浏览器后退返回前一视频重新选择 1080P。
7. 低清视频 document-start 注入，选择实际最高档位。
8. 新文档 document-start 注入，等待真实播放器初始化。

Auto 专项在同一 Edge 环境共 4 个检查点全部通过：曾打开后关闭菜单、从未打开菜单两种场景下，注入前都实际观测到 Auto、`hd1080` 与解码高度 1080；单次原生选择后原生列表勾选固定 1080P、主设置摘要不含 Auto。随后以可信 Enter 手动选择 Auto，脚本状态为 `manual` 且 `manualOverride=true`，没有新增固定档位动作。

因此本轮真实网站合计 12 个检查点通过。专项早期尝试曾因移动菜单鼠标点击超时，改用原生可信 Enter 激活；YouTube 的 Enter 处理器可能产生自己的非可信 Auto 点击，测试保留原始动作日志并区分该用户请求与脚本固定档位动作，不能把它误计为第二次自动写入。早期失败均未计入通过。

这些联网检查直接执行生产源码，没有安装 Tampermonkey 扩展，也没有使用日常账号资料。当前播放器资源仍为 `0229cd64/player_es6.vflset/en_US/base.js`。自动化工具曾错误假设“之前打开过菜单，关闭后选项 DOM 就一直存在”，并且未去除设置摘要的前导空格；相应失败未计为通过，已按实际菜单生命周期修正断言。Auto 准备流程还需恢复播放以完成其自身排入的格式切换，记录注入前实际档位，不能将请求的准备档位冒充观测值。

## 未验证与兼容性边界

本轮没有在真实 Tampermonkey 扩展中重跑完整安装 / 配置流程，没有逐一实测直播、首播等待室、Shorts 滑动、播放列表自然自动播完、移动站点、Music、所有账号实验及广告组合。旧版历史记录不能代替本版相同场景的验证。

所有内部 API、原生菜单标识、标签结构与广告标记仍可能随 YouTube 更新变化；不能承诺永久有效。Range 回退仅确认首选返回值，不能保证所有变体的原生菜单同步退出 Auto。首选值、实际解码档位和用户偏好不是同一个信号，生产脚本不持续纠正解码结果。无法可靠识别或确认时有界退出，以保护用户选择及正常播放。
